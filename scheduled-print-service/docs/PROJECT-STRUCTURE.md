# Project Structure

This document explains the organization of the Scheduled Print Service project.

## Folder Organization

### `/ScheduledPrintService/` - Main Project
Contains the C# source code and configuration files.

**Key Files:**
- `Program.cs` - Application entry point
- `appsettings.json` - Service configuration
- `ScheduledPrintService.csproj` - Project file

**Folders:**
- `Services/` - Business logic and service implementations
- `Models/` - Data models and DTOs
- `publish/` - Build output (generated, not in git)

### `/docs/` - Documentation
All markdown documentation files.

**Files:**
- `README.md` - Main project documentation
- `INSTALL.md` - Installation instructions
- `API-POLLING-GUIDE.md` - API configuration guide
- `CHAINING-GUIDE.md` - Action chaining documentation
- `MONITORING-GUIDE.md` - Logging and troubleshooting
- `TOKEN-RENEWAL.md` - Authentication guide
- `PROJECT-IMPROVEMENTS.md` - Future enhancements
- `PROJECT-STRUCTURE.md` - This file

### `/scripts/` - PowerShell & SQL Scripts
Deployment, configuration, and maintenance scripts.

**Installation & Deployment:**
- `install-service.ps1` - Install Windows service
- `uninstall-service.ps1` - Remove service
- `deploy-to-server.ps1` - Deploy to production
- `deploy-api3-fix.ps1` - Deploy specific fix
- `migrate-database-only.ps1` - Database-only deployment

**Configuration:**
- `configure-database.ps1` - Database setup wizard
- `create-database.ps1` - Initialize new database
- `add-picklist-api.ps1` - Add picklist API config
- `add-personalized-orders-api.sql` - SQL migration

**Diagnostics:**
- `check-database.ps1` - Verify database
- `check-service-permissions.ps1` - Check permissions
- `diagnose-logs.ps1` - Analyze logs
- `diagnose-service-issue.ps1` - Service troubleshooting

**Development:**
- `dev-reset-data.ps1` - Reset development data
- `dev-use-local-data.ps1` - Use local database
- `clear-processed-ids.ps1` - Clear processed orders

**SQL Scripts:**
- `api_config.sql` - Database schema
- `*.sql` - Migration scripts

### `/data/` - Runtime Data (Not in Git)
Runtime data files that should never be committed to version control.

**Contents:**
- `api_config.db` - SQLite database (copied to output during build)
- `error.txt` - Error logs
- `output.txt` - Output logs
- `printed-urls.txt` - Tracking file

**Git Ignore:**
All files in this folder are ignored except `.gitignore` and template files.

### `/logs/` - Application Logs
Serilog log files organized by date.

**Format:** `log-yyyyMMdd.txt`

**Retention:** Logs older than 30 days are automatically deleted.

### `/out/` - Generated PDFs
PDF files generated by the service.

**Naming:** `yyyyMMdd_HHmmss_ActionName-OrderId.pdf`

### `/screenshots/` - Diagnostic Screenshots
Screenshots captured when errors occur during PDF generation.

**Naming:** `error_yyyyMMdd_HHmmss_OrderId.png`

### `/chromium-cache/` - Browser Cache
Puppeteer Chromium download cache. Auto-managed by PuppeteerSharp.

## Build & Publish Flow

### Build Process
1. Reads source from `/ScheduledPrintService/`
2. References `../data/api_config.db` (via Link in .csproj)
3. References `../scripts/install-service.ps1` (via Link in .csproj)
4. Outputs to `/ScheduledPrintService/bin/Release/`

### Publish Process
1. Runs build
2. Copies referenced files to output
3. Outputs to specified folder (e.g., `/ScheduledPrintService/publish/`)
4. **Excludes** `/data/` folder from publish
5. **Excludes** `/scripts/` folder (except explicitly linked files)

### What Gets Published
```
publish/
├── ScheduledPrintService.exe
├── ScheduledPrintService.dll
├── appsettings.json
├── api_config.db              ← Copied from ../data/
├── install-service.ps1        ← Copied from ../scripts/
├── runtimeconfig.json
└── [dependencies]
```

## Development Workflow

### 1. Local Development
```bash
# Work in ScheduledPrintService folder
cd ScheduledPrintService

# Database is at ../data/api_config.db
# Scripts are in ../scripts/

# Build
dotnet build
```

### 2. Testing Changes
```bash
# Use development scripts
cd ../scripts
.\dev-use-local-data.ps1
.\dev-reset-data.ps1
```

### 3. Deployment
```bash
# Build and publish
cd ScheduledPrintService
dotnet publish --configuration Release --output publish

# Deploy to server
cd ../scripts
.\deploy-to-server.ps1
```

## File References in Code

### Database Path
```csharp
// Development: ../data/api_config.db
// Runtime: ./api_config.db (copied to output)
var dbPath = Path.Combine(AppContext.BaseDirectory, "api_config.db");
```

### Data Root
```csharp
// Configured in appsettings.json
"DataRoot": "C:\\ProgramData\\ScheduledPrintService"
```

### Logs
```csharp
// Relative to DataRoot
var logsPath = Path.Combine(dataRoot, "logs");
```

## Git Ignore Rules

### Ignored Folders
- `/data/` - All runtime data
- `/logs/` - All log files
- `/out/` - All generated PDFs
- `/screenshots/` - All diagnostic screenshots
- `/chromium-cache/` - Browser cache
- `/ScheduledPrintService/bin/` - Build output
- `/ScheduledPrintService/obj/` - Build intermediate
- `/ScheduledPrintService/publish/` - Publish output

### Tracked Files
- All source code in `/ScheduledPrintService/`
- All documentation in `/docs/`
- All scripts in `/scripts/`
- Project configuration files
- `.gitignore` files

## Best Practices

### Adding New Scripts
1. Place in `/scripts/` folder
2. Document in this file
3. Reference in main README if user-facing

### Adding Documentation
1. Place in `/docs/` folder
2. Link from main README
3. Use relative links between docs

### Database Changes
1. Create SQL migration in `/scripts/`
2. Test with dev database in `/data/`
3. Document in deployment guide
4. Never commit `/data/api_config.db` to git

### New Features
1. Update relevant documentation
2. Add any new scripts to `/scripts/`
3. Update this structure document if folders change
